SONORA APP ICON REBRANDING
Validation date: 2026-11-26

Scope: phone launcher icons and their selector only. The broader UI/performance
refinement remains pending. No playback, package IDs or networking protocols changed.

Implemented
- Default keeps the existing Sonora midnight-blue vector foreground/background.
- Light uses an off-white background and dark navy waveform.
- Dark uses a black background and silver waveform.
- Monochrome uses white and black with no gradients.
- All variants copy the exact five official waveform paths and 108dp/1024-unit
  viewport. Android supplies the launcher mask; no Samsung/Pixel-specific shapes.
- Every adaptive icon has the same pure-alpha monochrome waveform for native
  themed icons. The selector renders the adaptive resources themselves.
- Removed 169 obsolete launcher/preview icon files and 33 obsolete icon labels.
  Light/Dark reuse existing localised strings.
- Four new LauncherSonora* aliases replace all 23 legacy aliases. A fresh default
  alias is enabled in the manifest, independent of legacy disabled overrides.
- New choices are persisted and reconciled at application startup/package update.
  Legacy or unknown choices migrate to Default. No automatic launch or playback
  commands are issued by migration.
- API 33+: atomic batch alias updates. API 26-32: enable the chosen alias before
  disabling alternatives. Every change uses DONT_KILL_APP; the activity and media
  service remain the same. Older launchers may refresh their cache asynchronously.

Known limitations
- Full phone unit suite: 1354 cases, 1336 passed, 17 failed, 1 skipped.
  All 17 failures are LocaleStringsTest completeness failures for 50 existing
  Replay/Automix keys, unrelated to icon resources. They remain for the broader
  localisation work; no translation placeholders were added to mask failures.
- Other Android versions/OEM launchers were not device-tested. No configured
  emulator was available. API 26-32 switching uses the guarded legacy API path.
- The phone was locked at the final manual UI check, so visual verification used
  native drawable renders; an unlocked home-screen/selector inspection is pending.
- Process continuity was tested. Continuous audible playback during switching
  was not separately measured; playback implementation was not modified.
